## 3.12 v1.9.4（压缩包导入防崩 / Leaflet 离线外链修复 / 筛选实时计数）

**问题背景（用户实测）**：
- 导入 1.7G 照片压缩包，点击导入后 APP 直接崩溃 / 无法响应 / 死机。
- 运行中出现 `网页无法打开 位于 https://leafletjs.com/ 的网页无法加载，因为 net::ERR_CONNECTION_TIMED_OUT`。
- 要求筛选过程中实时提示「有几个建筑物、几张照片」。

**根因（已代码证实）**：
- 压缩包崩因：`webkitZipPhotos` 原流程 `buf = await f.arrayBuffer()`（整包 1.7G 一次性入内存）+ `IO.unzip` 把**每个条目解压后的字节都堆进 `files[name]` 不释放**（全部照片字节同时驻留）+ `for` 循环同步 `IO.bytesToB64` 逐张转 base64（再叠加 dataURL/SHA 多重拷贝）。峰值内存 ≈ 原包 + 全部解压字节 + 全部 base64 ≈ 3~5G，手机 WebView 直接 OOM 被杀；且同步循环卡死主线程 → ANR 被杀。体积预检仅 `confirmLargeTransfer`（流量提醒），放行后照旧全量入内存。
- Leaflet 超时根因：`initMap()` 用 `attributionControl: true`，地图默认渲染「Leaflet」署名前缀，硬链 `https://leafletjs.com`（见 `lib/leaflet.js` 中 `prefix:'<a href="https://leafletjs.com"...>'`）。全项目 Leaflet 资源已本地 `lib/`，无任何外部 CDN，唯此一处外链；离线/弱网点该链接即超时。
- 筛选计数：原 `#fHit` 仅显示命中建筑物数，未含照片张数（用户要求两者都显示）。

**修复（三项）**：
① 压缩包导入防崩：`zipSizeRefuse(f)` 体积预检——`f.size > 1.2GB` 直接弹窗拒绝并引导「按管理所拆成 ≤500MB 分卷」；`300MB~1.2GB` 二次确认后流式导入。`IO` 新增 `unzipStream(buf, onEntry)`（逐条目回调、处理完即 `data=null` 释放，不再全量驻留）与 `unzipCount(buf)`（仅统计照片数供进度）。`webkitZipPhotos` 改为 `await f.arrayBuffer()` → `unzipCount` → `unzipStream` 逐张 `receivePhoto` + 每 16 张 `await new Promise(r=>setTimeout(r,0))` 让出主线程 + 进度弹窗（`.bar`/`.bar-fill`）。`webkitZipSheets` 同步加 `zipSizeRefuse` 护栏。
② Leaflet 离线外链修复：`initMap()` 改为 `L.map(..., { attributionControl: L.control.attribution({ prefix: false }) })`，去掉默认署名外链。
③ 筛选实时计数升级：`openFilter` 提示区 `#fHit` 改为同时显示 `命中 <b id="fHitB">N</b> 个建筑物 · <b id="fHitP">M</b> 张照片`；`liveCount` 实时累计命中照片总数，`liveCount`/`refreshHit` 随条件勾选即时刷新。

## 5. 文档同步约定（每次需求变更必须执行）
为落实「以后每次增加或变更需求时同步文档」，建立以下硬性流程：

1. **变更前**：在本文档 §3 追加一条「待实施」记录，注明需求来源与预期版本号。
2. **变更中**：修改 `shuili_app/` 代码/数据；同时更新相关设计文档（见映射表）。
3. **变更后（交付前）**：
   - 递增版本号，在本文档追加正式变更记录（含实跑验证结论）；
   - 刷新版本快照 `shuili_versions/vX.Y.Z_日期/`；
   - 如数据结构/字段变化，同步更新《详细设计》§2/§3 与《需求说明书》§6。
4. **文档映射表**：

| 变更类型 | 必须更新的文档 |
|----------|----------------|
| 新增/修改功能 | 需求说明书(FR)、详细设计(模块)、变更文档(版本记录) |
| 字段/数据结构变化 | 需求说明书(§6)、详细设计(§2/§3) |
| 架构/模块调整 | 概要设计(§2/§4/§7)、详细设计 |
| 图标/UI/样式 | 需求说明书(§5)、变更文档(版本记录) |
| 底图/令牌/部署 | 需求说明书(§8)、概要设计(§9) |
| 回退/版本 | 变更文档(§4) |

> 本约定已写入项目记忆（`.workbuddy/memory/MEMORY.md`），维护人（旺仔）在每次会话启动时加载，确保变更不漏文档。
