## 1. 设计目标与原则
- **一套代码，两种形态**：同一套 H5（HTML/CSS/JS）既作为 PWA（浏览器/添加到主屏幕）运行，又通过 Android WebView 壳打包为 APK。
- **离线优先**：基础数据内嵌（`data.js`），前端资源本地化（Leaflet 本地库、图标本地），无网可用。
- **本地增量存储**：基础数据只读，用户改动以 delta 存 IndexedDB，支持重置/备份。
- **零后端、零 CDN**：全部逻辑在客户端完成，仅底图瓦片与定位需联网。
- **可回退**：版本化快照 + 文档同步，保证任意版本可恢复。

## 3. 部署拓扑
| 形态 | 部署方式 | 数据来源 |
|------|----------|----------|

## 6. 关键技术选型
| 技术 | 选型 | 理由 |
|------|------|------|
| 地图 | Leaflet 1.9.4（本地 lib/） | 轻量、离线友好、无依赖 CDN |
| 底图 | 天地图 WMTS（矢量 vec+cva / 影像 img+cia，可切换） | 国产合规底图 |
| 存储 | IndexedDB + localStorage | 浏览器/WebView 原生，离线持久化 |
| 压缩 | 自研 ZIP（store 写入；store/deflate-raw 读取）+ CRC32 | 零依赖、可控、奥维兼容 |
| 跨端 | PWA + Android WebView | 一套 H5，两形态，免重复开发 |
| 预处理 | Python 3（csv/json） | 开发期一次性融合，运行期不依赖 |

## 7. 数据模型（概要）
- **记录（Record）**：`{id,name,type,office,station,btype,lon,lat,params,photos,description,base}`（详见详细设计）。
- **增量 delta**：`{added:[Record], updated:{id:Record}, deleted:[id]}`。
  - 渲染 = 基础记录 − deleted + updated(覆盖) + added。
- **UI 偏好**：`{office:[], btype:[], basemap:bool, layer:"vec"|"img", center:{lat,lng,zoom}}`，存 localStorage。

---

## 8. 跨端方案
- PWA 与 APK **共用同一份 `shuili_app/` 前端代码**。
- 数据流差异：
  - PWA（`http(s)`）：`app.js` 优先用内嵌 `data.js`，否则 `fetch('data.json')`；注册 Service Worker 实现离线缓存。
  - APK：`file://` 加载，无 Service Worker、`fetch` 不可用，故**必须依赖内嵌 `data.js`**。
- 编译：`build_apk.sh` 同步 `shuili_app/`（排除 docs/中间文件）→ Gradle `assembleDebug` → 取出 APK。
